# Report template

The body should read in 5 minutes. Detail goes in the appendices. Keep these headings, because
`artifact-scan` and `to-prd` read the file, and `## Selection` is where a pick is recorded.

```markdown
# Ideation report — <project>

_<date> · commit `<hash>` · focus: <focus or "none"> · prior context: <loaded YYYY-MM-DD | none>_

## Selection

_Not yet selected._ (Later: `<title>` — first slice: <…>)

## Inventory summary

<Capability table from inventory.md (rows, status, evidence, job step), then 3–8 signal bullets
and the job map with empty steps flagged. On a rerun, mark rows that changed since the last pin.>

## Assumptions log

- A1: <assumption> — basis: code | user | none
- Q→A: <each question asked and the answer, verbatim and short>

## Market matrix

<Matrix from the market scan, including this product's column, the evidence-quality row and
steal/park/reject verdicts. One line on research value and the main gaps. Full deep-dives, user
voice and the search log are in Appendix B.>

## Insights

<Each one in the gate's form, tiered Insight / Hypothesis / Watch, with sources and the critic's
strongest counter-argument. Or: "None this run; conventional wisdom looks sound because …">

## Shortlist

<6–10 ideas in Kano order (must-be → performance → delighters), each using idea-template.md.
One line before the list: counts of deepen / extend / net-new, and how many sit outside the focus.>

## Cut table

| Idea | Reason |
|---|---|

## Appendix A — Parked

- <title> — <one line>. Interesting, maybe some day.

## Appendix B — Market detail

<The market-scan subagent's deep-dives, user voice, search log and gaps, pasted as returned.>

## Appendix C — Process

Raw candidates: N from 3 generators, axes: <…>, merges: <…>, recovery passes: <…>, critic
verdicts: <idea → holds/weakened/refuted>.
```
